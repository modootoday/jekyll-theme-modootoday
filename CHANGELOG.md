## [Unreleased]

### Added

- Static diagrams (adr:modootoday/20261105075445): front matter `diagrams: [{name, alt, caption, width, height}]` replaces the n-th ```` ```mermaid ```` fence with a committed light and dark SVG pair (`<modootoday.diagrams.dir><name>.svg` and `.dark.svg`) that follows the theme toggle, keeps the fence in a `details` element (`modootoday.diagrams.source: none` drops it), and works under `style-src 'self'` with no script. `modootoday-check` checks the number of fences against the entries, `alt` and the files, and proposes `width` and `height` from the SVG's `viewBox`. The Mermaid loader skips such pages. New interface label `diagram.source` in every catalog; component name `diagram`. The figure sheet grows by 79 bytes gzip (792 of its 896 cap). New Sass partials start at their 2.0 path (adr:modootoday/20261105075436).
- Fresh diagrams (adr:modootoday/20261105092848): `modootoday-check` reports a diagram SVG whose `data-mt-src` no longer matches its fence ("stale diagram"); an SVG without the attribute is not compared. `modootoday-check SRC --diagrams` prints the diagrams whose SVG is missing or stale as JSON (`page`, `name`, `line`, `fence`, `digest`, `files`, `reason`), needs no build and exits 1 when the list is not empty, for a pre-commit hook. In the repository, `script/figures/diagrams.mjs` renders that list with a pinned Mermaid (11.17.2, by URL and integrity) in Playwright's Chromium, a remote browser (`--cdp`) or the new Figures workflow, which fails on a stale SVG in `docs/` and can commit the renders; neither is in the gem. The Math and diagrams recipe (en, ko, ja) has a "Keep diagrams fresh" section, and CONTRIBUTING a "Rendering figures" one.
- Static math (adr:modootoday/20261105101229): `modootoday.math.mode: static` replaces the n-th ```` ```math ```` fence or `$$` block with the MathML of the n-th entry of `_data/math/<key>.yml` (`{src, html}`; `<key>` is the English source path with `/` as `--`, shared by translations, or front matter `math_key:`), so math needs no script, stylesheet or font and passes `style-src 'self'`. Each formula is a `figure.mt-figure.mt-math` around a focusable `div.mt-figure-scroll` region named by the new label `math.label` ("Formula [n]", in all 23 catalogs) and reuses the figure sheet's scroll rules plus one padding rule (15 bytes gzip, 831 of the unchanged 896 cap; the core sheet is unchanged). `modootoday-check` reports missing files, counts and entries rendered from other TeX ("stale math"), and inline math in static mode; `modootoday-check SRC --math` lists the files to write as JSON for a pre-commit hook, and the repository's `script/figures/math.mjs` writes them with KaTeX 0.19.0 in Node (not in the gem). KaTeX HTML output stays possible: the stylesheet is then linked only on pages that hold it, and the CSP needs `style-src 'unsafe-inline'`. `math.base: /assets/vendor/katex/` derives `src`, `css` and `auto_render_src` for the client loader. The docs site uses static math on the Math and diagrams recipe (en, ko, ja), which no longer claims that KaTeX's HTML passes a strict `style-src`.
- Charts from Markdown tables (adr:modootoday/20261105075724): with `modootoday.chart: {enabled: true}`, a paragraph holding only `` `chart:<type>` `` (`bar`, `line`, `area`, `pie` or `doughnut`, then `stacked` or `horizontal`) right before a table, or a `c: chart` section with its own table or `data: <name>` from `_data/charts/<name>.yml` (`{label, labels, series: [{name, values}]}`, written out as a table), renders `figure.mt-chart` around the table, with an emphasis-only paragraph as its caption. The table stays the figure's text, so readers without JavaScript, screen readers, github.com and Markdown twins get the numbers. Colours are the `--mt-chart-1` to `--mt-chart-8`, `--mt-chart-grid` and `--mt-chart-text` hooks, read with a default per scheme (every series at least 3:1 on the page background) in the new `chart` sheet (`data/chart.css`, linked only by pages with a chart; the core sheet is unchanged). `modootoday-check` checks types and options, the table after a `chart:` line, section data files, number cells and an unconverted `chart:` paragraph in the build; the label `chart.data` is in all 23 catalogs. Without the setting a `chart:` code span stays a code span. The Charts recipe (en, ko, ja), the components page and the kitchen sinks show both forms.
- Charts are drawn by the site's Chart.js (adr:modootoday/20261105093428): `modootoday.chart.src` names Chart.js 4, a version-pinned https URL with `integrity` or a site path (the theme still bundles no renderer), and pages with a chart load it and then the new `data/chart.js` module (with `data/chart-table.js` and `theme/current.js` preloaded), only when charts are on and the page does not set `chart: false`. The module draws a `canvas` with `role="img"` named by the caption, folds the table into a `details` labelled `chart.data`, takes its colours from the `--mt-chart-*` hooks, redraws with the other scheme's colours on the theme toggle or a system change without a reload, draws without animation under reduced motion, gives line series dash patterns, and leaves the table as it is under forced colours or without Chart.js. It works under the strict CSP (Chart.js sizes the canvas through the CSSOM). `data/chart.js` is 1,423 bytes gzip (cap 1,664) and `data/chart-table.js` 440 (cap 512); the chart sheet grows from 516 to 634 bytes gzip (cap 640 to 768). `modootoday-check` checks `chart.src` and `integrity` with the Mermaid and KaTeX rules. The docs site self-hosts Chart.js 4.5.1 (MIT) and draws the recipe and kitchen-sink charts; the docs QA gains a chart page type (left out of the page targets, as Chart.js is about 70 KB gzip), a CSP, contrast and feature check of the charts page, and the page in the visual and Lighthouse lists.
- Widgets (adr:modootoday/20261105105733): a `c: widget` section (params `widget`, `props`) or a paragraph holding only `` `widget:<element>` `` (props from front matter `widget_props`) places a site custom element registered with `element:` in `modootoday.scripts`, with its props as JSON in `data-props` and a light-DOM fallback (`div.mt-widget-fallback`: the section text, or the new `widget.fallback` sentence, in all 23 catalogs) that the new `widget` sheet (`media/widget.css`, 149 bytes gzip, cap 256) hides once the element is defined, with no `<noscript>`. The entry's module and sheet load only on pages that contain the element. The theme ships no widget code. `modootoday-check` reports an unregistered element, props that are not plain values, a section without a lead paragraph, an `element` with the theme's `mt-` prefix and an element named by two entries. A `widget:` line for an unregistered element stays a code span. The Widgets recipe (en, ko, ja) with a demo `x-counter` element, the components page and the kitchen sinks show both forms; the docs QA checks fallbacks, chart tables and diagram images with JavaScript off.
- Starter demo showcase (adr:modootoday/20261104170401, adr:modootoday/20261105122632): `modootoday.showcase: {enabled, style, starter, docs_url, use_url}`, set in a demo-only config file (`_config.demo.yml`), draws a 44 px bar above the header (or, with `style: pill`, a floating pill at the bottom centre) in the page's inverted colours, naming the theme and the starter and linking to the documentation and the template in a new window. It is a named region right after the skip link; the sticky header, anchor offset and sticky sidebar move down by the bar, which scrolls away in windows under 30rem tall, and the pill pads the page bottom. The hide button keeps it off for the visit in that tab: a pre-paint line (inline, or in `theme-init.js` with `csp: strict`) sets `html[data-mt-showcase=off]` before the next page paints, so nothing shifts. Every page of such a build carries `<meta name="robots" content="noindex">`. The `chrome/showcase.css` sheet (919 B gzip, cap 1,024) and `chrome/showcase.js` module (326 B, cap 384) load only when it is on; the core sheet is unchanged and a site without the key builds the same HTML. Labels `showcase.*` are in all 23 catalogs; `modootoday-check` validates the key in `_config.yml` and `_config.demo.yml`, warns when `_config.yml` itself turns it on, and, in a build that shows the showcase, warns about pages without the noindex tag (a site made from a starter keeps `_config.demo.yml` but builds without it).

### Changed

- Rendered starters (`rake starters:render`) also hold `_config.demo.yml`, the showcase settings of the starter's live demo, and their Pages workflow merges it into `_config.yml` for the build only when `github.repository` is the starter's own repository, so a fork or a repository created from the template builds as before (adr:modootoday/20261104170556, adr:modootoday/20261104171142). Each README names the live demo address. For contributors: `example/starters.yml` gains `demo.docs_url` and, per starter, `description`, `showcase: {style}` and `qa:` pages; `rake starters:demo` builds a demo as it deploys, `rake starters:repos` prints each repository's description, website and topics, and the Starters workflow runs the showcase audit on every demo build.

- `modootoday-check` now checks typed objects nested in JSON-LD and reports problems as warnings (errors in 2.0) (adr:modootoday/20261103053804, adr:modootoday/20261105112439). A single object under a property (`offers`, `organizer`, `acceptedAnswer`) was skipped before; it now gets the rules of its `@type` (required properties, vocabulary, absolute URLs, ISO 8601 dates), and each finding ends in "fix it now (in a nested object this is an error from 2.0)". Objects in arrays and top-level nodes keep their errors, a nested object without `@type` is not asked for one, and an empty answer stays an error. An event's `tickets:` gives an `offers` with only a `url`, which now warns about the missing price: the Detail layouts page shows `schema: {offers: ...}` with `price` and `priceCurrency`, and the docs event demo uses it. The Structured data and Upgrade guides (en, ko, ja) say so.

### Fixed

- Two or more code blocks that scrolled sideways on one page were all named "Code" (and tables "Table"), which axe reports as `landmark-unique` and screen readers list as identical regions (adr:modootoday/20261105110246). `content/scroll-region.js` now names each region by its `file:` title, caption, code language or nearest heading, numbered while names repeat ("Code, yaml 2"), through the new `region.named` and `region.nth` patterns in all 23 catalogs; tables follow the same rule. The module is 1,129 bytes gzip (cap 640 to 1,280).
- A `list` post list (the author page, `variant: list`) shifted the page down as its covers loaded in windows 48rem and wider: the cover dropped its 16:9 ratio there, so each row grew from the text's height to the image's (a layout shift of about 0.014 on the blog starter's author page). The cover keeps the ratio and fills the row as before.

## [1.5.0] - 2026-11-04

Visual: every page differs from 1.4.1 by design (flat overhaul); see [The 1.5 look](https://modootoday.github.io/jekyll-theme-modootoday/guides/upgrade/#the-15-look) in the Upgrade guide.

### Added

- On screens narrower than 30rem a site with a `logo` shows only the logo in the header, since the menu, search, language and theme buttons leave the name 73 to 127 px between 360 and 414 px. The name is hidden visually (`.mt-compact-title`), so it stays the link's accessible name, and the link keeps a 40 px target; a site without a logo is unchanged. `modootoday.header: {compact_title: false}` keeps the name, and `modootoday-check` validates the key (adr:modootoday/20261104115309).
- Site footer from data (adr:modootoday/20261104173945): `_data/nav/footer.yml`, or `footer-<lang>.yml` for a language, with `columns: [{title, items: [{title, url}]}]` and `copyright:`, printed by `modootoday/chrome/footer.html`, which the theme's `footer-custom.html` now includes (a site's own `footer-custom.html` still replaces it). Columns are lists labelled by their titles inside the footer landmark, not `nav` landmarks of their own, so a column titled Docs no longer repeats the sidebar's name (axe `landmark-unique`), in an auto-fit 10rem grid; their styles are the new `footer` component (`chrome/footer.css`), linked only when the footer has columns. With `language_switcher: footer` the switcher closes the footer. The docs site defines one in en, ko and ja.
- Search highlights the matched words (adr:modootoday/20261104173946): `chrome/search.js` wraps each occurrence of the query (or of each word with `match: terms`) in the result title and snippet in `mark`, built from text nodes, so the strict CSP holds and index text stays text; `.mt-search-results mark` has the `accent` fill. `search.js` grows from 1,279 to 1,500 bytes gzip and its cap from 1,408 to 1,664 bytes; it still loads on first use only.
- A site as `jekyll new` writes it (minima) builds with only its theme line changed. `layout: page` is a new layout, the `doc` layout under the name Jekyll, minima and jekyll-default-layout use, so `about.markdown` and a front-matter-less page on GitHub Pages get the doc pipeline instead of no layout. The CI builds such a site (`test/fixtures/sites/minima-shaped/`) on github-pages 232, Jekyll 4 and `remote_theme` and checks the About link, the home post list, the doc page, the post's author and date, no layout warning and a clean `modootoday-check`.
- The `home` layout lists the latest posts under the body when the page has no `hero:` and no `sections:` and the site has posts, as minima does; front matter `posts: true` or `false` decides on any home page, `list_title:` names the list and `show_excerpts:` (page, then site) shows or hides excerpts. It uses jekyll-paginate's paginator on `index.html`, else `modootoday.blog.per_page` posts and an archive link, and such a page loads the blog sheet. `modootoday-check` validates `posts` and `list_title`.
- Header navigation without `_data/nav`: `site/nav.html` reads `main` in `_data/navigation.yml`, then `header_pages` (page paths, minima), then, on sites of up to 100 HTML pages, every top-level HTML page (`/about/`) with a `title` in the page's language (`nav_order` first, then by title; `nav: false`, `nav_exclude: true`, hidden pages, the home page and machine layouts left out). `modootoday.nav: false` turns the titled-page list off, and `modootoday-check` now validates `modootoday.nav`. Lists built from pages make no nav groups, sidebar or previous/next links.
- Authors in every shape: `site/author.html` is the one reader of `authors`, `author` (a `_data/authors.yml` key, a name, a comma list, a list or a `{name, url, picture}` map), `modootoday.schema.author` and the site's `author:` (a name or minima's `{name, email}`). The byline, the Atom feed and JSON-LD use it, so a map no longer prints as pairs and posts without an author show the site's.
- Collection self-detail: when `defaults` or front matter give a collection document a list layout (`_portfolio/x.md` with `layout: portfolio`), a directory layout rendering a collection document without `items:`, `data:` or `records:` now draws it as the detail page of its family (`project`, `job`, `event` or `detail`, set by `mt_self_detail` on the layout) with that page's main class, `detail` bundle and structured data. The `detail` layout's markup moves to `modootoday/detail/page.html` (same output).
- `modootoday-check` reports, as an error, a layout that neither the site nor the theme has, in front matter of any source file (Markdown, HTML, posts, collections) or in `defaults`, and names the replacement for Minimal Mistakes layouts (`lib/modootoday/schema/compat/`); it warns about collection documents without a layout, which Jekyll writes without the theme because jekyll-default-layout covers only pages and posts, and names the layout to put in `defaults` (the detail page for a collection named like a theme list layout, else `doc`).
- Layouts in subfolders: `_layouts/<group>/<name>.html` is `layout: group/name` on Jekyll 3.10, Jekyll 4 and `remote_theme`, from front matter or `defaults`; tests pin it (`test/fixtures/sites/nested-layouts/`) before the theme ships layouts that way.
- Layout hooks, read as `var(--mt-<name>, <default>)` and never set by the theme, so a plain rule in a site stylesheet changes them: `--mt-sidebar-width` (18rem), `--mt-toc-width` (15rem), `--mt-doc-gap` (2rem), `--mt-doc-container` (90rem) and `--mt-code-radius` (`var(--mt-radius)`). Their defaults live in `_sass/modootoday/registry/_hooks.scss`, read through `mt-hook()`; the Customize guide (en, ko, ja) lists them. `modootoday-check` reports an undefined `var(--mt-…)` in the built CSS only when it has no fallback.
- Per-language font stacks: Korean, Japanese and Chinese (`zh-CN`, `zh-TW`) pages get their own `font-sans` (the system fonts of the script; for Korean, Pretendard first when the site loads it, which the theme does not ship), printed as `:root:lang(<code>)` only for the languages the site declares in `lang` and `modootoday.languages`. An English-only site prints none, and a site that sets `font-sans` in the token bridge or in `modootoday.tokens` keeps its font in every language. The default `font-sans` no longer lists Noto Sans KR and Noto Sans JP.
- Two semantic tokens: `border-input`, the border of form fields (#8a8a8a light, 3.45:1 on white; #737373 dark, 4.18:1 on the dark page), and `narrow` (40rem), the reading width for short single-column pages. The checker accepts both in `modootoday.tokens`, and `tokens.json` lists them. The docs QA now also measures `border-input` on the background (3:1), `border` on `card` (1.2:1) and `muted-foreground` on `accent`, the hover fill (4.5:1).
- Translations beside their sources: `guides/install.ko.md` next to `guides/install.md`, with `lang: ko` and `permalink: /ko/guides/install/` in front matter, is that page's Korean translation, as `ko/guides/install.md` still is. A language that translates only the home page can keep it as `home/index.<lang>.md`. `modootoday-check --i18n-pages` finds both layouts and reads each translation's `source_rev:`, the revision of the source it was translated from (`sha256:` and 12 hex digits of the source's `title`, `description`, `nav_title` and body, ignoring line endings and the generated page lists). A translation without one, or whose source changed since, is a warning that prints the current value, so sites with translations in `<lang>/` now see these warnings too. A translation beside its source whose `permalink` is not the source's URL under `/<lang>` is an error, and one without a source is a warning. Posts, record pages, lists of records and pages at a file URL such as `/404.html` need no translation. `modootoday-check --twins` finds a translation's twin by its URL, and both it and the optional plugin give an `llms.txt` and `llms-full.txt` to each language that has pages (before: each language folder); only the default language's root `llms.txt` lists the translations.
- Pages from data: `modootoday.records` declares record sets (`data`, `key`, `dir`, `permalink`, `layout`, `title`, `description`, `facts`, `labels`, `body`, `lang`), and `modootoday-stubs SRC --records[=SET,...]` writes one front-matter-only page per record of a `_data` JSON or YAML list (`<dir>/<key>.md` with the title, description, permalink, `record: <set>/<key>`, `record_index` and `twin: false`). The `detail` and `reference` layouts (and the detail layouts built on `detail`) read the record through `record_index` without scanning the data, fall back to a scan when the index is stale, and render the `facts` fields (lists as tags, values escaped) and the Markdown `body` field. A `reference` record page needs no `members:`. A directory page with `records: <set>` lists the set and links each card, and its JSON-LD list item, to the record page. Record keys must be URL-safe and unique, and a hand-written page is never replaced (exit 3). Running `--records` with `--twins` or `--aliases` plans the other stubs for the new record pages in the same run. `modootoday-check` reports a missing, stale or orphan record page with the same verdict as `--records --check`, and a `record:` naming no set. `modootoday-check --byte-exact=DIR[,DIR]` compares the SHA-256 of every file under the folders with the build and rejects folders under `_` or `.` (unless `include:` lists them) or in `exclude:`, files with front matter and files Jekyll converts. The example site has five sample records (`plugins/`) and a byte-exact `api/`; the docs site has a records demo and a Generated pages recipe (en, ko, ja); a `record` page type budget and a CI benchmark (`test/system/bench/records.rb`: 250 and 1,000 records with the Pages builder image, failing over 300 s) guard the cost. Sites without `modootoday.records` build the same HTML as before.
- `modootoday-stubs`, a second executable (Ruby standard library only) that writes the stub pages classic GitHub Pages needs. `modootoday-stubs SRC --twins` plans one `<name>.md.txt` per page, `--aliases` the URL aliases `modootoday.aliases: {md: true, html: true}` declares: `<name>.flat.md.txt` serves the twin again at `/<name>.md` and `<name>.html.md.txt` redirects `/<name>.html` to the page (meta refresh and canonical, no plugin, clean under a strict CSP). By default it only lists the creates, updates and deletes; `--write` applies them and touches only files whose content changes, `--check` exits 1 on drift for CI, `--no-prune` keeps orphan stubs and `--json` prints the plan. Exit codes: 0, 1 drift, 2 usage or `_config.yml`, 3 data (front matter, unsafe permalink, two pages with one alias, an alias over a source file). `modootoday-check --aliases` checks that every declared alias is in the build, that a flat alias is byte-identical to the twin and that an HTML alias points at the page, and reports the same conflicts; the checker rejects the flat alias with `twins: source`. Sites without `modootoday.aliases` build as before. RULES.md §5a and the Agents guide (en, ko, ja) describe both aliases.
- JSON-LD from page content: `modootoday.schema.faq: auto` (or `schema: {faq: auto}` on one page, `schema: {faq: false}` to opt out) makes a page with a `c: faq` section an `FAQPage` whose `Question`s and `Answer`s are read back from that section's details, so they match the visible text (code blocks left out); `schema.type` and `schema.mainEntity` still win. `schema: {type: DefinedTerm}` makes a page one term, linked to its glossary with `term_set:` and coded with `term_code:`; a glossary entry's `url:` adds that term page's URL. `LearningResource` (per page or through `schema.layouts`) takes `level`, `minutes`, `teaches` and `resource_type`, the course properties now shared with `Course`. `modootoday-check` validates `schema.faq` and reports an `FAQPage` without questions, a question with an empty answer and a `term_set` that is not a built glossary page. The Components page (en, ko, ja) turns `faq: auto` on.
- Search options under `modootoday.search`. For the index: `words` (default 300 words of each page's text, `0` for all of it), `collections` (collections with `output: true`, indexed after the posts), `fields` (front matter such as `[description, tags]`, put before the text) and `exclude` (URL prefixes left out, such as `[/v1/]`). For matching: `match: terms` (every word, in any order), `compact: true` (also compares with the spaces taken out, for Korean spacing) and `results` (default 8), which reach `search.js` as `data-match`, `data-compact` and `data-results` on the search box. Without the key the index, the search box and the results are as before. `modootoday-check` validates the keys, that each collection exists and has output, and warns when the built `search.json` is over 1.5 MB. New recipe: Search (en, ko, ja).
- List and table filter: `filter: true` or `filter: {facet: <column>}` on a `sections:` item (or on a page without `sections:`, or `filter_text: true` on a directory layout) adds `data-mt-filter` and a hidden search field with a count (`output[aria-live]`, i18n `filter.label` and `filter.count` in all 23 languages). `assets/js/modootoday/filter/filter.js`, an ES module that only those pages load, shows the field before the first list or table, hides the items that do not contain every word typed (NFC, case and spacing ignored, shared with `text/normalize.js`), and with `facet` adds one `button[aria-pressed]` per value of that table column; Escape clears the field. Without JavaScript every item stays visible. The optional `filter` sheet (about 0.4 KB gzip) is linked only on those pages. `modootoday-check` validates the value, that a list or table is there, that `facet` is within the table's columns, and rejects page `filter:` with `sections:` and `filter:` on `c: split`. New demo page: Filter (en, ko, ja), served under the strict CSP in the docs QA.
- Module scripts for section visuals: `modootoday.scripts` registers the site's ES modules by name (`{src, css, preload, element}`, site paths only), and `script: <name>` on `hero:` or a `sections:` item loads one on that page only: its sheet, a `modulepreload` hint per `preload` path and a `<script type="module">` in `<head>`, once per name. `poster:` (a path or `{path, srcset, sizes, width, height}`, the `hero.image` shape) puts `img.mt-visual-poster` first in the visual column, fetched with high priority on the hero and lazily in sections, so the first paint and the largest contentful paint come from a plain image. The module draws into a `.mt-visual-stage` and sets `data-mt-ready` on the `[data-mt-script]` column to hide the poster; without JavaScript, under reduced motion or when the module fails, the poster stays. A split item with `script:` or `poster:` needs no `visual:`. The new optional `visual` sheet (about 0.3 KB) is linked only on those pages. `modootoday-check` validates the entries, that their files are in the build, that `script:` names an entry and that a poster has `width` and `height` and exists. New demo page: Hero module (en, ko, ja), served under the strict CSP in the docs QA, measured by Lighthouse and shot by the visual run with reduced motion (poster only).
- `mt:themechange`: the theme toggle sends it on `document` after a click (`source: "toggle"`) and after a system colour-scheme change while the reader has not chosen one (`source: "system"`), with `detail.theme`. Two small ES modules for site scripts, loaded only when a module imports them: `assets/js/modootoday/theme/current.js` (`currentTheme()`, and `onThemeChange(callback)`, which also works without the toggle and calls back once per real change) and `assets/js/modootoday/dom/config.js` (`readConfig(element, defaults)` reads `data-*` settings). Both are public API.
- Token bridge: a site sets `$mt-overrides-base` (fonts, sizes), `$mt-overrides` (light) and `$mt-overrides-dark` in `_sass/modootoday/_site.scss`, which the theme imports before its settings in the core sheet and in every optional sheet. No inline style and no shadowed `assets/css/modootoday.scss` are needed, so it works under a strict CSP. `modootoday-check` allows only those three maps in the file, with token names the theme defines. The hook file and its maps are now public API.
- New semantic tokens `font-heading` and `heading-weight` (for `h1` to `h4`) and `link` and `link-hover` (links in running text). They default to `font-sans`, 650 and `primary`, so the default look is unchanged; `tokens.json` lists them, as DTCG aliases where they point at another token.
- `modootoday.site_css` (and front matter `site_css:`) links the site's own stylesheets after the theme sheets, with the same `?v=` query; `modootoday.preload` (and front matter `preload:`) adds `<link rel="preload">` hints before the stylesheets, with `crossorigin` for fonts and no query, so the URL matches the `@font-face` request. Front matter `mermaid: false` skips a page.
- Math: `modootoday.math` (off by default) renders ```` ```math ```` fences and `$$` blocks with KaTeX (`inline: true` adds `$…$`) on the pages that have one, through `assets/js/modootoday-math.js`. Front matter `math: false` skips a page.
- Checker: validates `modootoday.mermaid` and `modootoday.math` (https, exact version, SRI hashes), reports any third-party script or stylesheet in built pages unless it is a declared renderer URL with matching `integrity` and `crossorigin="anonymous"`, and warns about inline `$…$` when `math.inline` is false.
- Figures: an `.svg` figure (a diagram) reads in dark mode from one file (`--mt-diagram-filter-dark`, built on `--mt-img-filter-dark`; `none` turns it off, a `#light` path keeps one image as drawn) and, on narrow screens, keeps `--mt-figure-min-width` and scrolls sideways in a focusable region named by its alt text. - Budgets: each `assets/js/modootoday-<name>.js` bundle has its own 2 KB budget and does not count toward the core script.

#### Milestone 0.1

##### Added
- Gem-based Jekyll theme layout: `_layouts/{default,doc,twin,llms,llms-full}.html`, `_includes/{md-components,md-sections,head-custom}.html`, `_sass/`, `assets/`.
- Default stylesheet with CSS custom-property design tokens, light and dark (`prefers-color-scheme`) themes, callouts, status badges, sections, CTA buttons, tabs, focus-visible styles and a responsive doc layout.
- `assets/js/md-tabs.js`: Home/End keys, focusable panels (`tabindex="0"`), ids unique across several tab groups.
- `modootoday-check` executable (from the kit's `bin/check`): missing-front-matter error, unregistered alert type error, github-pages lockfile check now opt-in (`--github-pages[=VERSION]`), `--help`.
- Neutral example site (en/ko/ja) with agent-readable Markdown twins.
- Ruby tests (`test/check_test.rb`), jsdom tests (`test/tabs.test.js`), CI for the GitHub Pages stack and Jekyll 4, release workflow with RubyGems trusted publishing.

- md-components v1 amendments from the standards audit (66 fixtures in `test/fixtures/md`, built in-process by `test/build_test.rb`):
  - Alerts: case-insensitive types; standalone `<p>[!TYPE]</p>` (blank `>` line, body starting with code, list or heading); `[!TYPE]<br />` (trailing spaces).
  - Checker: case-insensitive markers, unregistered/empty/titled/formatted alerts and tab after `>` are errors, `<pre>`/`<code>` ignored when scanning build output; fence info string must be one language word; bare URL/e-mail autolinks, abbreviations and HTML comments forbidden; setext, nested, indented and commented `##` are errors; footnotes explicitly allowed.
  - `default` layout: `rel="alternate" type="text/markdown"` link to the twin and `rel="describedby"` link to the nearest `llms.txt`; example `llms.txt` files use llmstxt.org H2 link lists.

- Automatic twins and llms files: opt-in generator `plugins: [jekyll-theme-modootoday]` (`lib/`, Jekyll 3.9+/4, skipped by GitHub Pages safe mode) adds `<name>.md.txt`-equivalent twin pages and `llms.txt`/`llms-full.txt` per language; layouts `llms` and `llms-full` (with includes `md-raw-body`, `md-llms-pages`) generate those files from front-matter-only stubs on GitHub Pages. Example uses them.
- Checker `--twins`: stubs no longer required when the twin exists (plugin); clearer missing-twin hint; `twin: false`; `llms.txt` must start with an H1; `llms-full.txt` must contain every page body.
- `test/consumer_test.rb`: builds real consumer sites (theme gem with stubs, `--baseurl`, stub-less site with the plugin); CI builds the example with `remote_theme` pinned to the pushed commit.

##### Fixed
- Sections split only on top-level `<h2>`; an `h2` inside a quote, list or alert no longer injects `</section><section>` into it.
- Docs: alerts are a GitHub extension outside the GFM spec; the raw-HTML ban is about portability (GitHub renders `details`/`kbd`, strips others; kramdown passes all through), not "GitHub sanitising".
- Checker messages for `##` and alerts nested in quotes/lists explain why and what to use instead.
- `required_ruby_version` raised to 3.0 (the checker uses endless methods).
- Example: `sass.silence_deprecations: [import]` for Dart Sass; `llms.txt` per language generated instead of hand-written.
- Raw `<name>.md` copies in `_site` on GitHub Pages: caused by content files without front matter (rendered by `jekyll-optional-front-matter` and also copied). Front matter is now required and checked.
