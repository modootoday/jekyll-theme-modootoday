# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).
The content rules have their own version header (`md-components v1`) in [RULES.md](RULES.md).

## [Unreleased]

### Added

- Layout hooks, read as `var(--mt-<name>, <default>)` and never set by the theme, so a plain rule in a site stylesheet changes them: `--mt-sidebar-width` (18rem), `--mt-toc-width` (15rem), `--mt-doc-gap` (2rem), `--mt-doc-container` (90rem) and `--mt-code-radius` (`var(--mt-radius)`). Their defaults live in `_sass/modootoday/registry/_hooks.scss`, read through `mt-hook()`; the Customize guide (en, ko, ja) lists them. `modootoday-check` reports an undefined `var(--mt-…)` in the built CSS only when it has no fallback.
- Per-language font stacks: Korean, Japanese and Chinese (`zh-CN`, `zh-TW`) pages get their own `font-sans` (the system fonts of the script; for Korean, Pretendard first when the site loads it, which the theme does not ship), printed as `:root:lang(<code>)` only for the languages the site declares in `lang` and `modootoday.languages`. An English-only site prints none, and a site that sets `font-sans` in the token bridge or in `modootoday.tokens` keeps its font in every language. The default `font-sans` no longer lists Noto Sans KR and Noto Sans JP.
- Two semantic tokens: `border-input`, the border of form fields (#8a8a8a light, 3.45:1 on white; #737373 dark, 4.18:1 on the dark page), and `narrow` (40rem), the reading width for short single-column pages. The checker accepts both in `modootoday.tokens`, and `tokens.json` lists them. The docs QA now also measures `border-input` on the background (3:1), `border` on `card` (1.2:1) and `muted-foreground` on `accent`, the hover fill (4.5:1).
- Translations beside their sources: `guides/install.ko.md` next to `guides/install.md`, with `lang: ko` and `permalink: /ko/guides/install/` in front matter, is that page's Korean translation, as `ko/guides/install.md` still is. A language that translates only the home page can keep it as `home/index.<lang>.md`. `modootoday-check --i18n-pages` finds both layouts and reads each translation's `source_rev:`, the revision of the source it was translated from (`sha256:` and 12 hex digits of the source's `title`, `description`, `nav_title` and body, ignoring line endings and the generated page lists). A translation without one, or whose source changed since, is a warning that prints the current value, so sites with translations in `<lang>/` now see these warnings too. A translation beside its source whose `permalink` is not the source's URL under `/<lang>` is an error, and one without a source is a warning. Posts, record pages, lists of records and pages at a file URL such as `/404.html` need no translation. `modootoday-check --twins` finds a translation's twin by its URL, and both it and the optional plugin give an `llms.txt` and `llms-full.txt` to each language that has pages (before: each language folder); only the default language's root `llms.txt` lists the translations.
- Pages from data: `modootoday.records` declares record sets (`data`, `key`, `dir`, `permalink`, `layout`, `title`, `description`, `facts`, `labels`, `body`, `lang`), and `modootoday-stubs SRC --records[=SET,...]` writes one front-matter-only page per record of a `_data` JSON or YAML list (`<dir>/<key>.md` with the title, description, permalink, `record: <set>/<key>`, `record_index` and `twin: false`). The `detail` and `reference` layouts (and the detail layouts built on `detail`) read the record through `record_index` without scanning the data, fall back to a scan when the index is stale, and render the `facts` fields (lists as tags, values escaped) and the Markdown `body` field. A `reference` record page needs no `members:`. A directory page with `records: <set>` lists the set and links each card, and its JSON-LD list item, to the record page. Record keys must be URL-safe and unique, and a hand-written page is never replaced (exit 3). Running `--records` with `--twins` or `--aliases` plans the other stubs for the new record pages in the same run. `modootoday-check` reports a missing, stale or orphan record page with the same verdict as `--records --check`, and a `record:` naming no set. `modootoday-check --byte-exact=DIR[,DIR]` compares the SHA-256 of every file under the folders with the build and rejects folders under `_` or `.` (unless `include:` lists them) or in `exclude:`, files with front matter and files Jekyll converts. The example site has five sample records (`plugins/`) and a byte-exact `api/`; the docs site has a records demo and a Generated pages recipe (en, ko, ja); a `record` page type budget and a CI benchmark (`qa/bench/records.rb`: 250 and 1,000 records with the Pages builder image, failing over 300 s) guard the cost. Sites without `modootoday.records` build the same HTML as before.
- `modootoday-stubs`, a second executable (Ruby standard library only) that writes the stub pages classic GitHub Pages needs. `modootoday-stubs SRC --twins` plans one `<name>.md.txt` per page, `--aliases` the URL aliases `modootoday.aliases: {md: true, html: true}` declares: `<name>.flat.md.txt` serves the twin again at `/<name>.md` and `<name>.html.md.txt` redirects `/<name>.html` to the page (meta refresh and canonical, no plugin, clean under a strict CSP). By default it only lists the creates, updates and deletes; `--write` applies them and touches only files whose content changes, `--check` exits 1 on drift for CI, `--no-prune` keeps orphan stubs and `--json` prints the plan. Exit codes: 0, 1 drift, 2 usage or `_config.yml`, 3 data (front matter, unsafe permalink, two pages with one alias, an alias over a source file). `modootoday-check --aliases` checks that every declared alias is in the build, that a flat alias is byte-identical to the twin and that an HTML alias points at the page, and reports the same conflicts; the checker rejects the flat alias with `twins: source`. Sites without `modootoday.aliases` build as before. RULES.md §5a and the Agents guide (en, ko, ja) describe both aliases.
- JSON-LD from page content: `modootoday.schema.faq: auto` (or `schema: {faq: auto}` on one page, `schema: {faq: false}` to opt out) makes a page with a `c: faq` section an `FAQPage` whose `Question`s and `Answer`s are read back from that section's details, so they match the visible text (code blocks left out); `schema.type` and `schema.mainEntity` still win. `schema: {type: DefinedTerm}` makes a page one term, linked to its glossary with `term_set:` and coded with `term_code:`; a glossary entry's `url:` adds that term page's URL. `LearningResource` (per page or through `schema.layouts`) takes `level`, `minutes`, `teaches` and `resource_type`, the course properties now shared with `Course`. `modootoday-check` validates `schema.faq` and reports an `FAQPage` without questions, a question with an empty answer and a `term_set` that is not a built glossary page. The Components page (en, ko, ja) turns `faq: auto` on.
- Search options under `modootoday.search`. For the index: `words` (default 300 words of each page's text, `0` for all of it), `collections` (collections with `output: true`, indexed after the posts), `fields` (front matter such as `[description, tags]`, put before the text) and `exclude` (URL prefixes left out, such as `[/v1/]`). For matching: `match: terms` (every word, in any order), `compact: true` (also compares with the spaces taken out, for Korean spacing) and `results` (default 8), which reach `search.js` as `data-match`, `data-compact` and `data-results` on the search box. Without the key the index, the search box and the results are as before. `modootoday-check` validates the keys, that each collection exists and has output, and warns when the built `search.json` is over 1.5 MB. New recipe: Search (en, ko, ja).
- List and table filter: `filter: true` or `filter: {facet: <column>}` on a `sections:` item (or on a page without `sections:`, or `filter_text: true` on a directory layout) adds `data-mt-filter` and a hidden search field with a count (`output[aria-live]`, i18n `filter.label` and `filter.count` in all 23 languages). `assets/js/modootoday/filter/filter.js`, an ES module that only those pages load, shows the field before the first list or table, hides the items that do not contain every word typed (NFC, case and spacing ignored, shared with `text/normalize.js`), and with `facet` adds one `button[aria-pressed]` per value of that table column; Escape clears the field. Without JavaScript every item stays visible. The optional `filter` sheet (about 0.4 KB gzip) is linked only on those pages. `modootoday-check` validates the value, that a list or table is there, that `facet` is within the table's columns, and rejects page `filter:` with `sections:` and `filter:` on `c: split`. New demo page: Filter (en, ko, ja), served under the strict CSP in the docs QA.
- Module scripts for section visuals: `modootoday.scripts` registers the site's ES modules by name (`{src, css, preload, element}`, site paths only), and `script: <name>` on `hero:` or a `sections:` item loads one on that page only: its sheet, a `modulepreload` hint per `preload` path and a `<script type="module">` in `<head>`, once per name. `poster:` (a path or `{path, srcset, sizes, width, height}`, the `hero.image` shape) puts `img.mt-visual-poster` first in the visual column, fetched with high priority on the hero and lazily in sections, so the first paint and the largest contentful paint come from a plain image. The module draws into a `.mt-visual-stage` and sets `data-mt-ready` on the `[data-mt-script]` column to hide the poster; without JavaScript, under reduced motion or when the module fails, the poster stays. A split item with `script:` or `poster:` needs no `visual:`. The new optional `visual` sheet (about 0.3 KB) is linked only on those pages. `modootoday-check` validates the entries, that their files are in the build, that `script:` names an entry and that a poster has `width` and `height` and exists. New demo page: Hero module (en, ko, ja), served under the strict CSP in the docs QA, measured by Lighthouse and shot by the visual run with reduced motion (poster only).
- `mt:themechange`: the theme toggle sends it on `document` after a click (`source: "toggle"`) and after a system colour-scheme change while the reader has not chosen one (`source: "system"`), with `detail.theme`. Two small ES modules for site scripts, loaded only when a module imports them: `assets/js/modootoday/theme/current.js` (`currentTheme()`, and `onThemeChange(callback)`, which also works without the toggle and calls back once per real change) and `assets/js/modootoday/dom/config.js` (`readConfig(element, defaults)` reads `data-*` settings). Both are public API.
- Token bridge: a site sets `$mt-overrides-base` (fonts, sizes), `$mt-overrides` (light) and `$mt-overrides-dark` in `_sass/modootoday/_site.scss`, which the theme imports before its settings in the core sheet and in every optional sheet. No inline style and no shadowed `assets/css/modootoday.scss` are needed, so it works under a strict CSP. `modootoday-check` allows only those three maps in the file, with token names the theme defines. The hook file and its maps are now public API.
- New semantic tokens `font-heading` and `heading-weight` (for `h1` to `h4`) and `link` and `link-hover` (links in running text). They default to `font-sans`, 650 and `primary`, so the default look is unchanged; `tokens.json` lists them, as DTCG aliases where they point at another token.
- `modootoday.site_css` (and front matter `site_css:`) links the site's own stylesheets after the theme sheets, with the same `?v=` query; `modootoday.preload` (and front matter `preload:`) adds `<link rel="preload">` hints before the stylesheets, with `crossorigin` for fonts and no query, so the URL matches the `@font-face` request. Both take site paths only. `modootoday-check` validates their shape and that each file is in the build. New recipe: Brand tokens, with a made-up teal palette and a self-hosted open-licence heading font (docs only); the docs QA checks its contrast in light and dark mode and serves it under the strict CSP.
- `modootoday.code_theme: github` colours code blocks with GitHub's light and dark palettes (github-light-default and github-dark-default from tm-themes 1.12.12, editor background and text included); the default `theme` keeps the theme palette. Rouge classes its tokens differently from the editor, so the palette matches GitHub's, not every word. Ten finer code tokens join the five existing ones: `code-background`, `code-foreground`, `code-variable`, `code-type`, `code-number`, `code-operator`, `code-tag`, `code-attribute`, `code-inserted` and `code-deleted`; they default to the colours those Rouge classes had, so the default look is unchanged. The token bridge overrides the preset. `modootoday-check` validates the value and warns when the site does not highlight with Rouge. The docs QA checks every code colour against the code background in light and dark mode, on the default palette and on a new GitHub code colours demo page.
- `modootoday.asset_version` (`theme`, `build` or `false`) sets the `?v=` query on the theme's CSS and JavaScript URLs, so a CDN can cache them for long and still pick up a new release; `build` adds the commit (`site.github.build_revision`, or the build time where the Pages builder does not pass one). `modootoday-check` validates the value. New guide: Performance (what each page loads, versioned URLs, a CDN cache rule, the size budgets).
- Docs QA: a CSP audit opens sample pages, among them a new strict CSP demo page, with a strict `Content-Security-Policy` response header and fails on any violation or console error. Size budgets now also cover, per page type (docs, landing, blog, component showcase), the gzip bytes of the CSS and JavaScript one page loads.
- Starter sites: `example/` holds three, `docs`, `blog` and `landing`, each a Jekyll site that builds on its own, listed in `example/starters.yml` (repository, languages, stacks, `modootoday-check` flags). `rake starters:render` writes each one for the `github-pages` stack (`remote_theme` pinned to this version) and the `jekyll4` stack (the theme gem) to `pkg/starters/<stack>/<name>/`, adding a `Gemfile` from `gemfiles/`, a `README.md` and a Pages workflow (build, `modootoday-check`, deploy) from one template each, and the stubs from `modootoday-stubs`; it copies no interface catalog, so starters pick up the theme's strings from each release, and the docs starter's catalogs keep only the strings it changes. Two renders are byte-identical; `rake starters:check` fails on drift and `rake starters:build` builds and checks every starter. Publishing them to their own repositories comes after 1.5.0; there is no `starters:publish` task yet.

### Changed

- The optional theme sheets move once to their final context paths, `assets/css/modootoday/<ns>/<id>.css` (adr:modootoday/20261104053143): `docs/doc.css`, `chrome/search.css`, `chrome/terminal.css`, `content/loading.css`, `content/lists.css`, `content/inline.css` (was `content.css`), `media/figure.css`, `media/visual.css`, `structure/bleed.css`, `data/filter.css`, `data/table.css` and `data/table-stack.css`. Only the `<link href>` of pages that use them changes; the rules, the link order and the names that front matter `css:` and layout `mt_sheets` take are the same, except that the unreleased `content` name is now `inline`. Sass partial paths do not move.
- Callouts, quotes and figures in the flat style. A callout is a hairline box with 1rem padding; its type colour reaches only the 16px icon and the 14/20 title (weight 600, was 650). Body quotes have a 2px start rule (was 3px), and a `c: quote` section is no longer a filled card but a larger quote (18/28) with the same rule and a muted 14/20 attribution. Figure images, SVG figure frames and embeds have 8px corners (`radius`, was `radius-lg`), captions are 14/20, and `.mt-illustration-tag` sits above the picture instead of covering it. The news correction note takes the warning colour its `data-variant` names. Horizontal rules get 3rem around them (was 2.5rem). The callout, figure and embed rules move from the core sheet to a new context sheet, `content/inline.css`, which only pages whose body has a callout, a figure, an illustration or an embed link; the partials keep their `components/core/inline/` paths, so a site that shadows one still changes it, and `modootoday.css: bundle` still folds them into the core sheet. The core sheet shrinks from 26,833 to 25,102 bytes; `content/inline.css` is 1,686 bytes (budget 2 KiB).
- Tables: every table in the page body is wrapped in `div.mt-table` when the page is rendered, and its styles move from the core sheet to two context sheets that only pages with a table load: `data/table.css` (probe `<table`) and `data/table-stack.css` (probe: a variant class on a table). The core sheet shrinks from 27,132 to 26,833 bytes; `table.css` is 2,318 bytes and `table-stack.css` 914. The look is flat: 14/20 text with tabular figures, horizontal rules only, header cells in weight 500 and the muted colour with no fill, and no outer border or radius. The wrapper scrolls instead of the table, and a shade at an edge shows that more is there. Tables of two or three columns keep each column at least 5rem wide (the last one 9rem) and scroll past that; tables of four or more columns may grow to about 9rem per column (36, 45 and 54rem for four, five and six), scroll, and keep the first column in view. Code in the first column and right- or center-aligned cells stay on one line. `scroll-region.js` makes the wrapper, not the table, the labelled focusable region. `modootoday.components` gains `table` and `table-stack`, always included. The download layout's table and the reference package table use the same wrapper (`table.mt-mk-table`, `table.mt-dx-pkgs`; their own `div` wrappers are gone), and the filter puts its controls before the wrapper.
- Opt-in table variants by kramdown attribute list: `{: .mt-table--stack}` turns rows into blocks with each cell labelled by its column below 40rem, `{: .mt-table--dl}` puts each key above its value, and `{: .mt-table--fixed}` gives equal columns that wrap anywhere. `c: params` tables stack by default. The stacked forms apply once `table-stack.js`, a script only those pages load, has set the table roles and the labels, so without JavaScript the table scrolls. `modootoday-check` still reports attribute lists as not portable.
- Docs QA budgets are per file: every theme stylesheet and script has a gzip cap on its row in `assets/registry.html` (measured plus 10%, rounded up to 128 bytes), and a page type's limit is the sum of the caps of what its pages load (adr:modootoday/20261104053146). A row without a cap fails with the value to use, and so does a theme file without a row. The total of all theme scripts, the CSS one page links, the showcase limit and the hand-kept page-type limits are gone; 8 KiB CSS, 6 KiB JavaScript and six theme sheets per page are guide targets that warn. `scroll-region.js` grows from 482 to 501 bytes gzip; the stacked-table labels are a separate 519-byte `table-stack.js`.
- Code blocks are 14px on a 24px line with 1rem padding, and their corners follow the new hook `--mt-code-radius` (default `var(--mt-radius)`, 8px; was `radius-lg`). A `file:` title is a 40px bar on the code background. The copy button is a 32px icon button at the top end of the block, in the title bar when there is one, named by its `aria-label` (the `code.copy` string, as before) with no visible text; a polite status region says "Copied" (`code.copied`) after a copy. Untitled blocks keep a 40px strip above the code for the button at every width (was only below 48rem), so it never covers the first line. Inline code is a chip on the `accent` fill with tighter padding. `code-copy.js` grows by 69 bytes gzip. Package names in reference package tables are plain code, underlined on hover only.
- Doc pages use wider columns: from 64rem an 18rem sidebar beside the 45rem text column, from 80rem the 15rem "On this page" column as well, with a 2rem gap (was 12rem, 12rem and 14rem with gaps of 2.5 to 3.5rem), and pages with a sidebar widen the header, main and footer to 90rem. A doc page without a sidebar or TOC centres the 45rem measure (was 52rem). The page meta line, the pager and the back-to-top link start on the text column at every width. Sidebar links are 14px in 32px rows, the current one filled at weight 500; group titles are 12px, muted, without capitals; TOC links are 14px in 28px rows under a 14px title. Every hero clears the page actions menu.
- The header is one row of `header-height` (4rem) at every width. Below 64rem the header links give way to a menu button (`details.mt-menu.mt-nav-sheet` inside `nav.mt-nav`, labelled by the new interface string `nav.menu` in all 23 languages) that opens a full-width sheet with the top-level links and each group's links under the group title; Escape, the arrow keys and an outside click close it as in the other menus. The row no longer scrolls sideways or wraps onto a second and third line, and the inline copies of group links, `li.mt-nav-flat`, are removed (a site that styled them styles `.mt-nav-sheet` instead). Below 48rem search is a 2.5rem icon field that covers the header row while it has focus, with the results under it; from 48rem it is 2rem high and 15rem wide. The language and theme buttons are 2.5rem (were 2.25rem). The header rules move from `layout/_shell.scss` to `components/core/chrome/_header.scss`, which the core sheet always includes. Anchors are offset only by `scroll-padding-top`: headings, legal headings and the reference pages' members, letters and terms no longer add a `scroll-margin-top`. The visual regression run adds 600 and 720px, and the docs QA checks the header height at four widths on four layouts, the last anchor of two long pages and the menu sheet by keyboard.
- A role-based type scale on a 4px baseline: `h1` 32/40, `h2` 24/32, `h3` 20/28 and `h4` 16/24 at every width (the smaller phone sizes are gone), with -0.02em tracking and balanced line breaks (`text-wrap: balance`); Korean, Japanese and Chinese headings have no negative tracking and a taller line (44, 36 and 32). The scale, tracking and motion defaults are Sass maps read at build time, so the core sheet prints no new custom property. Japanese text uses `line-break: strict` and, where the browser supports it, `word-break: auto-phrase`.
- A flat, neutral default look; token names stay, values change. The gray ramp is neutral (#fafafa to #0a0a0a; muted text #6b6b6b, 4.89:1 on the #f5f5f5 hover fill), and dark mode has three layers: page #0a0a0a, cards #171717, hairlines #2e2e2e. Headings and `strong` use weight 600 (was 650), body text a 1.75 line height (was 1.7), and `measure`, `container` and `header-height` become 45rem, 75rem and 4rem (were 46rem, 76rem and 3.75rem); `space-section` is 4rem (was 3rem). `shadow-sm` is `none`, and `shadow` is a soft overlay shadow left only on menus and search results. The header is opaque (no blur), callouts are plain bordered boxes with the type colour on the title only, and buttons, keyboard keys, pager links, cards, link cards, plans and post cards lose their shadow and lift. The dark `theme_color` default follows the page background to #0a0a0a. The Migrate and upgrade guide (en, ko, ja) has a 1.4 to 1.5 row and a token bridge snippet that restores the 1.4 values.
- The example site is split by content into the three starters: the guide, records and Korean and Japanese pages go to `docs`, the posts, news, author and feed to `blog` (its home is the former `/blog/` page), and `landing` is new. The sources no longer commit twin stubs, record pages or a `Gemfile`; the render writes them. The front-matter-less site moves to `test/fixtures/sites/source-mode/`. CI builds the starters in a new `starters.yml` workflow (each starter on github-pages 232 and Jekyll 4, with `remote_theme` at the pushed commit, and on the GitHub Pages builder image), which replaces the example steps and the `pages-action` job of `ci.yml`; `rake` runs `starters:build` instead of the `example` task.

- The docs site keeps each translation beside its English page: `docs/guides/install.ko.md` and `docs/guides/install.ja.md` next to `docs/guides/install.md`, and the home pages of the 20 languages that translate only the home page in `docs/home/` (`docs/home/index.vi.md`). `script/docs-index` writes their `lang:` and `permalink:`, and `script/docs-index --stamp PATH...` records the `source_rev:` a translator has caught up with; every translation is stamped at its current source. The per-language `defaults` scopes are gone, and `modootoday.full_languages: [ko, ja]` turns on the `--i18n-pages` report. Every URL is unchanged. The "Edit this page" links of the translations point at their new paths. The Korean and Japanese Resume and Links demos show the new file name where the person's name belongs (`resume.ko.md` for `resume.md`); that comes from a known layout bug, where `page.name` is always the file name. On the classic builder a few links in translations stay relative instead of being made absolute, with the same targets. Three links now name their target by URL: the Korean and Japanese feed links on the Blog and news page, which would otherwise reach the English feed, and the Japanese kitchen-sink image, which was broken on Jekyll 4.
- `search.json` lists pages in URL order. Before, it followed the order Jekyll read the files in, so renaming or moving a source file could reorder the index. The entries are the same; only their order changes, once. Posts and collections keep their own order after the pages.
- `script/docs-index` writes the docs site's twin stubs through the same code as `modootoday-stubs --twins`; the stubs it writes are unchanged. The docs site keeps every file a tool writes under `docs/generated/`: the twin stubs and the per-language `llms.txt` and `llms-full.txt` stubs, which `script/docs-index` now also writes. Each stub sets `path:` to where it used to sit, so every URL is unchanged and the built site is byte-identical, with one exception. On the classic builder, the `llms.txt` links in the Korean and Japanese Agents guides now reach that language's `llms.txt`, as they always did on Jekyll 4. `modootoday-check --twins` also finds a page's stub there. User sites and `modootoday-stubs` are unchanged. `script/readme-commands` also generates the `modootoday-stubs` table in the READMEs.
- `search.js` is rewritten one statement per line and compares the query and the text in Unicode NFC, so text written in decomposed form (an accent or a Hangul syllable as separate code points) now matches; otherwise its results are unchanged. It grows from 856 to 1,217 bytes gzip, and its size limit from 1 to 1.2 KiB. The core scripts total 8,586 bytes gzip (was 6,432), with `filter.js`, `chips.js` and `text/normalize.js`, which no page loads unless it uses a filter; the budget rises from 7 to 9.25 KiB, the blog page type (which also loads `search.js`) from 4.25 to 5 KiB, and the filter demo gets its own page type.
- `modootoday.components` gains `filter`, always included like `visual`; with `css: bundle` its rules fold into the core sheet.
- `theme-toggle.js` is rewritten one statement per line; apart from the new `mt:themechange` event it behaves as before. The total of the core scripts grows from 5,228 to 6,432 bytes gzip (the two helper modules, which no theme page loads by itself, and the longer toggle); its budget rises from 5.75 to 7 KiB.
- `modootoday.components` gains `visual`, always included like `lists`, `bleed` and `terminal`; with `css: bundle` its rules fold into the core sheet.
- The core sheet adds the four new tokens to `:root` (`link` and `link-hover` also to the dark-scheme rules); headings take `font-family` and `font-weight` from them and links their colour, so the built CSS changes while the rendered pages look the same. An empty `_sass/modootoday/_site.scss` builds byte-identical CSS and HTML to having none.
- The Customize guide recommends the token bridge and `site_css` instead of shadowing `assets/css/modootoday.scss`; the docs starter ships a commented-out `_sass/modootoday/_site.scss`.
- The core sheet adds the ten code tokens to `:root` and the dark-scheme rules, and `pre` takes its background and text colour from `code-background` and `code-foreground`; the computed colours of the default theme are unchanged.
- Theme stylesheet and script URLs now end in `?v=<theme version>` by default (`asset_version: theme`), which changes the built HTML of every page. GitHub Pages ignores the query. Set `modootoday.asset_version: false` to keep the previous URLs.
- `code-copy.js` loads only on pages with a code block (or with the page actions menu), and `scroll-region.js` only on pages with a code block or a table; before, both loaded on every page. What they do is unchanged.
- The docs site sets `modootoday.csp: strict`, so its pre-paint theme script comes from `theme-init.js` instead of an inline script.
- Ruby 3.3 is now the oldest supported Ruby (`required_ruby_version >= 3.3`); Ruby 3.2 has reached end of life. CI tests Jekyll 4 on Ruby 3.3 and 3.4, and also runs Ruby 4.0 as an allowed-failure entry.
- Faster builds on large sites: the layouts and includes no longer scan `site.pages` once per lookup on every page. Each layout builds one list of page URLs per page (`modootoday/lookup/urls.html`); existence checks (twin, language home, `llms.txt`, feed, `search.json`) read it, the breadcrumb and its JSON-LD take the home and parent pages by their position in it (`lookup/page.html`, `lookup/crumbs.html`), and `ref-url.html` searches only the pages that have a `ref`. On a synthetic 1,000-page site the GitHub Pages build took less than half the time. The built output is unchanged.
- CI: pushes to `main` run only the fast jobs (the Ruby and Jekyll matrix, the classic Pages builder, JS and tokens), and a newer push cancels the older run. Docs QA, Lighthouse and visual regression run on pull requests and in the release check; the visual run compares with the latest release tag (`RELEASING.md` step 3).
- The optional stylesheets and theme scripts now come from one table, `modootoday/assets/registry.html` (one row per file: its triggers, separated by `^`, its Sass parts, its gzip size cap and a module's imports; section sheets are rows too, and the files the layouts link themselves are listed for their caps). `stylesheets.html` links context sheets through `assets/sheets.html` and the `default` layout writes its script tags through `assets/scripts.html`. `mt_context_sheets` and `mt_section_sheets` are derived from it. The built output is unchanged.
- `modootoday-check` source is grouped by context under `lib/modootoday/check/` (`config/`, `page/`, `build/`, `registry/`, `source/`, `layouts/`), and the `modootoday:` settings in `_config.yml` are validated from a declarative key schema (`config/schema.rb`, one file per key group in `config/keys/`) instead of one chain of checks. Messages, their order and exit codes are unchanged; a new snapshot test pins the full output on sample sites.

### Deprecated

- `--mt-p-space-3` (0.75rem): the theme no longer uses it. It stays in the core sheet for sites that read it and goes in the next major version.

### Fixed

- Diff blocks showed each added line beside the removed one, off screen, because the line spans were inline blocks; they now stack. From 48rem the copy button covered the end of long first lines.
- With a doc sidebar, "Edit this page" and its rule sat 8px off the text column; a split hero was squeezed beside the page actions menu; the focus ring of "On this page" links was clipped by the scrolling column.
- Below 64rem the header showed only the first group's links and grew to two or three rows (105 to 139px, depending on the layout), so anchor targets landed under it on phones; between 30rem and 48rem the search icon sat outside its field.
- Inline code in table cells no longer breaks letter by letter (even at 1440px): the table scrolls instead. A five-column Korean table at 360px had cells 18 lines tall and "고객, 역할" one syllable per line; English configuration keys broke inside the word.
- Korean table columns no longer shrink to one syllable at narrow widths (a configuration key 49px wide, a 26-line description cell at 360px). Korean text kept `word-break: keep-all` with `overflow-wrap: anywhere` on every element, and `anywhere` lets a box shrink below its longest word; it now uses `overflow-wrap: break-word` on the element that carries `lang="ko"`, which still breaks a word that would overflow its line.
- The Japanese showcase hero no longer cuts off its heading at narrow widths: the hero applied `word-break: keep-all` in every language, so a long Japanese line could not break and the hero's clip hid the rest. Keep-all now applies to Korean only, as in running text, and the docs QA checks the Korean and Japanese home heroes at 360px.
- `llms.txt` names each translation with the theme's language name (`日本語`, `한국어`) when the site's `_data/i18n/<lang>.yml` has no `language:` key, as the language switcher already did. Before, it printed the bare code.
- `modootoday-check` no longer reads a Markdown file that `exclude:` names, such as a repository `README.md`, as a page. Before, it skipped only excluded folders, so a site that excluded its `README.md` failed with front matter and badge errors for a file Jekyll never builds.

- The `resume` heading and the Person or Organization `name` in the JSON-LD of `resume` and `links` pages showed the page's file name (`resume.md`, `resume.ko.md`) instead of the documented `name:`, on Jekyll 4 and on GitHub Pages, because Jekyll replaces `name:` on a page with its file name. The key is now `display_name:`; without it the title is used, never the file name. A `name:` that Jekyll keeps (on a collection document) is still read. `modootoday-check` warns on a `resume` or `links` page with `name:` (rename it) or with neither key, and a `resume` without `display_name:` or a title is an error. The Documents, Marketing, Personal site and Migrate pages (en, ko, ja) and the demo pages use `display_name:`.
- The Customize guide no longer says any theme `_sass/` file can be replaced by a site file at the same path. Only the partials the theme imports through the Sass load path can: the token hook, `_access.scss` and the component partials. The others are imported relative to the theme file, so Sass reads the theme's copy on GitHub Pages and on Jekyll 4, and a site copy of `_core.scss`, `_sheet.scss` or a per-layout `_index.scss` stops the build. A consumer test pins this on both stacks.
- `modootoday-check` accepts `figure-svg` in `modootoday.components`. The theme already ships it as the SVG figure sheet part, but a site with a shorter component list could not turn it on because the checker rejected the name.
- The feature request form and a JSON-LD test fixture quote flow-mapping values that hold `, ` or end in `?`, so they also parse with older libyaml (0.2.2, the system copy on Ubuntu 22.04).

- **Doc sidebar:** `doc` pages get a sidebar built from the nav groups (`modootoday.sidebar: auto | true | false`, default `auto` = on when the nav has groups; `sidebar: false` in front matter). From 64rem it is a sticky column; below, a collapsed menu above the page shows the current group, replacing the horizontally scrolling link row. With a sidebar the header drops the flat group links.
- **Page actions:** on pages with a Markdown twin, a menu offers View as Markdown, Copy page and Copy for AI (source URL, then the Markdown). `modootoday.page_actions: false`, front matter `page_actions: false`, or leaving `page-actions` out of `components` removes it. Labels (`page_actions.*`, `sidebar.label`) ship in all 23 catalogs.
- `color_scheme: auto-dark` and `auto-light` start in that scheme and keep the toggle; the start is printed as `data-theme` in the HTML, so there is no flash and no `head-custom.html` script.
- **Blog and news layouts:** `blog` (paginated index of post cards with `variant: list | grid | magazine`, featured first, per-language), `news` (front page with lead, secondary stories and `news_sections` blocks), `news-article` (dateline, deck, breaking/live badges, correction, sources), `author` (profile and posts) and `feed` (per-language Atom). The `post` layout gains a byline from `_data/authors.yml` (`author:` or `authors:`), published/updated dates, reading time, cover image, series box, previous/next, related posts, a share button, `BlogPosting`/`NewsArticle` JSON-LD and OG `article:*` tags. Settings live under `modootoday.blog` and `modootoday.news`; labels are translated in all 23 catalogs. Liquid only (classic GitHub Pages and Jekyll 4). The styles (`modootoday-blog.css`) and `share.js` are a separate optional bundle loaded only by these layouts, with their own size budgets; the core bundles are unchanged. `modootoday-check` validates the settings, `_data/authors.yml` and post front matter. See [Blog and news](docs/layouts/blog-news.md).
- **Result container for CTA sections:** when a `c: cta` section holds an element with `data-mt-result`, the `.mt-cta` box (centering, gradient, border) goes on that element instead of the whole section. Sections without one render exactly as before. The docs Components page uses it, so the Buttons example card matches the other cards and only its result is framed.
- `visual: <name>` on a `sections:` item and `hero: {visual: <name>}` render a site-provided `_includes/sections/<name>.html`; `modootoday-check` fails when it is missing.
- `full_width: true` front matter removes the reading-column width of `main` (`.mt-main-full`).
- Breadcrumb: the home crumb uses the home page `short_title:` when set.
- `modootoday-check` accepts tool region markers alone on a line (`<!-- spec:toc:begin -->` / `<!-- spec:toc:end -->`); other HTML comments are still errors.
- `modootoday.hreflang` keeps `hreflang` alternates when `seo: false`.
- **Icons:** `modootoday/brand/icon.html` renders inline SVG icons (`name`, `size`, `label`, `class`) in `currentColor`, decorative unless labelled, with directional icons mirrored in RTL. Every former text, emoji or CSS-drawn icon (language globe, theme sun/moon, search, nav chevron and external link, breadcrumb separators, alert types, copy/check, edit link, previous/next, tag and category badges) now uses it. See the [API page](docs/reference/api.md#stable-names).
- **Logo and favicon:** `modootoday.logo: brand | <path>` shows the modootoday mark (or your image) before the site title through the overridable `modootoday/brand/logo.html`; `modootoday.favicon: brand | <path>` links an SVG, 32 px PNG and Apple touch icon. The docs site uses both.
- **Built-in translations:** set `lang:` and the theme's labels (skip link, navigation, callouts, status badges, table of contents, pagination, code copy, search, language menu) are localized for 23 languages with nothing to copy, on GitHub Pages and Jekyll 4. A site `_data/i18n/<lang>.yml` overrides individual keys; unknown languages use English. `modootoday/t.html` prints a label by key. `modootoday-check --i18n-init` copies a catalog to edit, and `--i18n` checks keys and placeholders; `.yaml` catalogs are rejected.
- **Language switcher:** `modootoday.language_switcher: header | footer` renders a theme-level switcher from `languages` (the same alternates as `hreflang`), linking to the translation of the current page or that language's home page. In the header it is a globe button with a `<details>` dropdown (localized accessible name, `aria-current`, `lang`/`hreflang` on each link) that keeps the same width however many languages there are; in the footer, a list. Nothing renders with fewer than two languages. `modootoday/lang-switch.html` can be included from a custom footer. The docs site uses the header menu in place of its footer list.
- `menu.js` (small, CSP-safe): Esc closes a `<details class="mt-menu">` and returns focus, arrow keys move between items, an outside click or opening another menu closes it. Used by the language menu and the nav "More" group.
- On screens under 30rem, search takes its own row under the site title.
- **Tag and category archives:** the `archive` layout (`archive: tags | categories`) and the `modootoday/archive.html` include list terms with post counts and one anchored section per term, filtered by language (`archive_lang: all` for every post). With `modootoday.archive: {tags: /tags/, categories: /categories/}` the `post` layout adds a footer linking each tag and category. Liquid only, so it works on classic GitHub Pages; one page per taxonomy, not per term. `modootoday-check` validates `modootoday.archive` and skips twins for `_posts/`. The post and archive styles ship in the optional `modootoday-blog.css` bundle (loaded by the `post`, `archive` and blog/news layouts; `blog_css: true` opts any other page in, for example one that uses the `modootoday/archive.html` include). See the [API page](docs/api.md#posts-and-archives).
- Slot contract: `slots:` in `_data/components.yml` declares the named parts of a section (`lead`, `items`, `panels`, `actions`, `code`, `figures`) with `required`/`min`/`max`; `modootoday-check` counts them per section. Markup is unchanged. See the [API page](docs/api.md#slot-contract).
- Slot contract: `slots:` can be a list of alternative forms (a section passes when it satisfies one; `steps` and `timeline` accept a list or `###` panels), and `parts:` declares the stable selectors of a component, checked against the component structure table of `api.md` when the site has one. See the [API page](docs/api.md#slot-contract).
- **Right-to-left:** `dir="rtl"` from `lang` for RTL languages, `direction:` front matter override, logical properties in component CSS, LTR code inside RTL text, RTL-aware tab arrow keys, and an RTL kitchen sink checked in docs QA.
- [Math and diagrams](docs/recipes/math-diagrams.md) guide (en, ko, ja): KaTeX and Mermaid under a strict CSP, rendered at build time or self-hosted. The theme bundles neither.
- Japanese documentation on the docs site (`/ja/`), with hreflang, Markdown twins, `llms.txt` and a footer language switcher on the docs site.
- Guide pages in Korean and Japanese on the example site, with twins and `llms.txt` entries.

### Fixed
- Pages no longer flash on load: the header search box and light/dark toggle are drawn from the first paint instead of popping in when their scripts run (the header used to jump, most visibly after clicking the logo), and the toggle icon matches the colour scheme immediately. QA checks the first frames after a logo click.
- Tabs: the tab list no longer shows a vertical scrollbar (the active-tab underline overflowed it by 1px); it scrolls sideways only, and the focus ring sits inside each tab. QA fails on any tabs scrollbar at 360/768/1280px.
- Search on a page whose language has no other pages (the RTL sample) now prefers the site's default language instead of every language.
- The table of contents sits a fixed gap after the text at wide widths instead of being pushed to the far edge; the narrow-screen menu row fades at its end to show it scrolls; inline code in cards no longer breaks inside a file name; figures are dimmed slightly in dark mode.
- The header site title links to the current language's home (`/<lang>/`, with `baseurl`) instead of the default-language root, for every language in `languages` including right-to-left ones; it falls back to the site root when that language has no home page.

### Changed
- **Previous/next follows the nav:** pagination walks `_data/nav` in order, a group's own page and then its items, instead of top-level entries only.
- Doc-only includes live under `_includes/modootoday/doc/` (`pagination.html`, `sidebar.html`, `page-actions.html`, `twin.html`); the page-actions script is part of `code-copy.js`.
- **One prefix, no aliases:** every class and custom property is `mt-*` / `--mt-*`; the `md-*` classes, `--md-*` properties, `$mt-md-aliases` and the checker's alias warnings are gone (they were never released). The skip-link target is `#mt-main`.
- Theme includes and scripts live under `modootoday/`: `_includes/modootoday/markdown/{components,sections,raw-body,llms-pages}.html` and `assets/js/modootoday/tabs.js` (were `_includes/md-*.html` and `assets/js/md-tabs.js`); tab ids are `mt-tabs-*`.
- `since:` version badges are not part of 1.0: they are no longer rendered and `modootoday-check` reports any `` `since:…` `` code span as an error.
- The docs site and the README quick start build CSS with `sass: {style: compressed}` (Ruby Sass 3.7 and Dart Sass): the stylesheet is about 10 % smaller with identical rendering. `qa/css-sizes.rb` reports the size of the core and each component.
- Header, navigation, search, theme toggle and code copy use logical properties, so they mirror in right-to-left pages; the code Copy button sits at the inline end and never covers code. The docs navigation lists the math and diagrams guide.
- `modootoday-check` validates `_data/components.yml` itself: unknown keys in a component entry (allowed: `params`, `i18n`, `slots`, `parts`) or a slot rule (allowed: `required`, `min`, `max`), non-integer or negative counts and `min` greater than `max` are errors, reported once per registry instead of once per section. Registries that use only these keys are unaffected.
- `modootoday-check` also looks up each `parts:` selector in the built HTML of the pages that use the component (inside its `section[data-c]`), when Nokogiri is available as it is under `github-pages`; parts added by component scripts (`role=`, `aria-*`) are checked after the scripts run by the docs site QA. The kitchen sink now shows `timeline` in both forms.
- The `caution` token is now rose (`#b8174a` light, `#ff7b9c` dark) instead of red, so caution alerts no longer read as the orange-red brand link colour. New primitives `--mt-p-rose-400/600`.
- Search results show the current language first, title matches before body matches, and a muted text snippet; on narrow screens the results panel spans the header width.
- Footnotes are rendered after the last section instead of inside it (they no longer land in a call-to-action card).
- On screens under 48rem, code blocks with a Copy button start below the button so it never covers the first line.
- The rules are final: `RULES.md` and every file header now say `md-components v1` instead of `md-components v1 (draft)`. No rule changed.
- The public API is documented on the docs site; changes are listed in this CHANGELOG.
- `modootoday-check` also warns on `md-*` classes and `var(--md-*)` in the site's own includes, layouts, CSS and pages (code is ignored), not only in Sass.
