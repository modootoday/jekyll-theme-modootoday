# ガイド

最初の 3 つから読んでください。インストール、設定、移行とアップグレードで、サイトがテーマの上で動きます。その後のトピック別ガイドはそれぞれ 1 つの主題を扱うので、必要な順に読めます。

<!-- spec:docs-index:begin -->
- [インストール](install/) — 従来の GitHub Pages のサイトや Jekyll 4 のサイトにテーマを追加し、スターターのテンプレートから始め、テーマのチェッカーでビルドを確認します。
- [設定](configuration/) — _config.yml の modootoday キーに書くサイト全体の設定をすべてまとめ、それぞれの既定値、変わる点、詳しく説明しているページを示します。
- [移行とアップグレード](upgrade/) — 別の Jekyll テーマからサイトを移す方法、既存のプロジェクトにテーマを導入する方法、バージョン間でアップグレードするときに変える点を順に説明します。
- [最初のページ](first-page/) — github.com でもサイトでも同じように読めるページを front matter、セクション、アラートで書き、そのページが従ういくつかの Markdown のルールを覚えます。
- [カスタマイズ](customize/) — トークンとトークンブリッジで色、角丸、フォントを変え、独自のスタイルシートを足したり Sass パーシャルを上書きしたりして、テーマをサイトに合わせる方法を説明します。
- [AI エージェント](agents/) — ページごとの Markdown 版、URL エイリアス、llms.txt、llms-full.txt を公開し、AI エージェントがサイトを書いたとおりに読めるようにします。
- [アクセシビリティ](accessibility/) — キーボード操作、スクリーンリーダー、スマートフォンのセーフエリア、タッチターゲットの大きさ、ハイコントラスト、視差効果を減らす設定への対応を説明します。
- [パフォーマンス](performance/) — ページごとに読み込むファイル、CDN で長くキャッシュするためのバージョン付きアセット URL、CI が守るサイズ予算を説明し、サイトを軽く保つ方法を示します。
- [構造化データ](structured-data/) — テーマが全ページに出力する schema.org JSON-LD グラフに何が入るかと、発行者、著者、ページの種類などの値を設定する方法を説明します。
- [サイトを翻訳する](translate-site/) — 自分のサイトを複数の言語で公開する手順を、言語の一覧、ページの翻訳、言語ごとのホームページとメニューから、欠けた翻訳や古い翻訳を見つける検査まで順にまとめます。
- [翻訳ルール](translation/) — 韓国語と日本語のドキュメントと UI の文言を翻訳するときに守る正式なスタイルルール、文体、用語集、そしてそれを検査するツールをまとめます。
