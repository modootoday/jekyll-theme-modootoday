# インストールできるサイト

> [!NOTE]
> このページは[英語の原文](../../../recipes/pwa/)の翻訳です。内容が異なる場合は英語版が優先されます。

`modootoday.pwa` をオンにすると、ブラウザーがサイトをウェブアプリとしてインストールできます。Chrome、Edge、Android はインストールボタンを表示し、iOS と macOS の Safari はサイトの名前とアイコンのままホーム画面や Dock に追加します。テーマはすでにある設定からウェブアプリマニフェストを作るので、同じ値を二度書く必要はありません。サービスワーカーはテーマのファイルと読者が訪れたページを保存し、オフラインでも読めるようにします。既定はオフで、この設定がないサイトは以前とまったく同じにビルドされます。

## オンにする

```yaml
modootoday:
  favicon: brand
  pwa:
    enabled: true
    short_name: Docs   # アイコンの下に出る名前。12 文字以内に
```

リモートテーマはサイトのルートにファイルを追加できないため、小さなファイルをいくつかリポジトリに置きます。gem に入っているスタブ作成ツールで書き出します。

```sh
modootoday-stubs . --pwa           # 書き出すファイルを一覧表示
modootoday-stubs . --pwa --write   # 下のファイルを書き出す
```

| ファイル | 内容 |
|---|---|
| `manifest.webmanifest` | ウェブアプリマニフェスト |
| `sw.js` | サービスワーカー。ワーカーは自分のフォルダーの下のページだけを扱うため、サイトのルート(`baseurl` を含む)に置きます。 |
| `offline.md` | `/offline/` のオフラインページ。`modootoday.full_languages` の言語ごとに `/<lang>/offline/` の `offline.<lang>.md` も作ります。 |

どのファイルにも front matter と include が 1 つ、または front matter だけが入っています。これらのファイルをコミットしてください。すべてのページが `<link rel="manifest">` でマニフェストをリンクし、ワーカーを登録する小さなスクリプトを読み込みます。サイトをビルドして `modootoday-check . _site` を実行すると、設定、ファイルが存在して最新か、ビルドされたマニフェストとアイコン、全ページのリンク、ワーカーとワーカーが保存するページを確認します。

作成ツールはこれらのファイルを削除せず、同じパスに自分で作ったファイルがあれば上書きせずに終了コード 3 で止まります。

## マニフェストに入る値

| マニフェストのフィールド | 取得元 |
|---|---|
| `name` | `pwa.name`、なければサイトの `title` |
| `short_name` | `pwa.short_name`、なければ名前。ホーム画面は 12 文字程度より長い名前を切り詰め、`modootoday-check` が警告します。 |
| `description` | `pwa.description`、なければサイトの `description` |
| `lang`、`dir` | サイトの既定言語(`lang:`)とその書字方向 |
| `start_url`、`id` | `pwa.start_url`。`/guides/` のようなサイト内のパス(既定は `/`)の前に `baseurl` を付けた値。クエリ文字列は使えないため、アプリがトラッキング用パラメーター付きで開くことはありません。 |
| `scope` | 常に `baseurl` を付けたサイトのルート(例: `/docs/`)。設定キーではありません。 |
| `display` | `pwa.display`: `standalone`(既定、アドレスバーのないウィンドウ)、`minimal-ui`、`browser` |
| `theme_color` | `modootoday.theme_color`。ブラウザーのバーのタグと同じ色で、ライトの値、`color_scheme: dark` ではダークの値。`theme_color: false` では入りません。 |
| `background_color` | `pwa.background_color`(16 進数の色)、なければページの背景: `#ffffff`、`color_scheme: dark` では `#0a0a0a` |
| `icons` | `pwa.icons`: `brand`(既定)または独自のリスト |

## アイコン

`icons: brand` は `favicon: brand` と同じくテーマのマークを使います。192px のアイコン、512px のアイコン、そして Android が円形に切り抜いてもマークが円の中に収まる 512px の maskable アイコンです。独自のアイコンを使うには、サイトの PNG ファイルを列挙します。

```yaml
modootoday:
  pwa:
    enabled: true
    icons:
      - {src: /assets/icons/app-192.png, sizes: 192x192}
      - {src: /assets/icons/app-512.png, sizes: 512x512}
      - {src: /assets/icons/app-maskable.png, sizes: 512x512, purpose: maskable}
```

- purpose が `any`(既定)の 192px と 512px のアイコンは必須です。どちらかがないと、ブラウザーはインストールを提案しません。
- `maskable` のアイコンを推奨します。絵柄は幅の 80% の中央の円に収め、正方形全体を背景で埋めてください。
- `sizes` はファイルと一致させます。`modootoday-check` はビルドされたサイトから各 PNG の実際のサイズを読み取ります。
- `favicon` が `brand` でないのに `icons` を設定しないと、アプリにテーマのマークが表示されるという警告が出ます。`icons:` に独自のアイコンを書くか、そのまま使うなら `icons: brand` と書きます。

Apple のタッチアイコンは以前と同じく `favicon` から来ます。Safari 16.4 以降もマニフェストを読みます。

## インストールできるか確認する

1. サイトをビルドし、HTTPS か `localhost` で開きます。
2. Chrome のデベロッパーツールを開き、Application、Manifest に進みます。インストールできる場合、Installability の項目には何も表示されません。
3. 公開する前に `modootoday-check . _site --strict` を実行します。

シークレットウィンドウでは Chrome は常にインストールできないと報告します。通常のウィンドウで確認してください。

## オフラインで読む

ワーカーが扱うのは、スコープ内にあるサイト自身への `GET` リクエストだけです。フォーム、ほかのサイト、埋め込み、CDN などそれ以外のリクエストは以前どおりネットワークへ送られ、ワーカーの中で失敗したリクエストもネットワークへ送られます。

| リクエスト | ワーカーの動作 |
|---|---|
| `POST`、ほかのオリジン、サイト外のパス、`Range` ヘッダーのあるリクエスト(音声、動画) | 何もしません。ブラウザーが通常どおり取得します。 |
| テーマのファイル(`/assets/css/modootoday*`、`/assets/js/modootoday*`) | 保存したコピーを返し、なければ取得して保存します。 |
| ページ | 読者が最新版を見られるよう、まずネットワークから取得します。オフラインなら保存したコピーを、なければそのページの言語のオフラインページを返します。サーバーエラー(5xx)のときも保存したコピーを返します。成功した応答だけを、最大 50 ページまで保存します。 |
| `search.json` | 保存したコピーを返し、次回のために新しいコピーを取得します。 |
| Markdown 版、`llms.txt`、フィード、`sitemap.xml`、マニフェスト、`sw.js` | 何もしません。常にネットワークから取得します。 |
| サイト自身の CSS と JavaScript(`site_css`、`scripts`) | まず取得し、オフラインなら保存したコピーを返します。 |
| 画像とフォント | 保存したコピーを返し、新しいコピーを取得します。最大 60 ファイルまで保存します。 |

ワーカーはインストール時に、オフラインページとそのページがリンクするファイル、`start_url`、`pwa.precache` のパス、front matter に `pwa: precache` があるページを保存します。

```yaml
modootoday:
  pwa:
    enabled: true
    precache: [/guides/, /reference/api/]   # サイトのパス。クエリ文字列なし
```

初回の訪問のたびにこのリストをすべてダウンロードするので、短く保ってください。リストのページがビルドにないと `modootoday-check` が失敗し、リストが 1 MiB を超えると警告します。読者が最初に開いたページはまだワーカーを通りません。ワーカーの準備ができると、そのページが読み込んだ URL をワーカーに送るので、読者がオフラインでサイトを開いても見た目が崩れません。

オフラインページはオフラインであることを伝え、再試行(求めたページを読み込み直す)とホームへのリンク、この端末でワーカーが保存しているページの一覧を表示します。サイトマップと検索インデックスには入りません。

### キャッシュ、バージョン、同じオリジンのサイト

キャッシュの名前にはサイトのパスが入ります。`mt:<baseurl>/:assets:<version>`、`mt:<baseurl>/:pages:<build>`、`mt:<baseurl>/:media` です。そのため、同じ `<user>.github.io` にあるプロジェクトサイト同士がお互いのキャッシュに触れることはありません。

- ページのキャッシュはデプロイのたびに入れ替わります。名前にテーマのバージョンとコミット(またはビルド時刻)が入ります。
- テーマのファイルのキャッシュは `modootoday.asset_version` に従います([パフォーマンス](../../guides/performance/#バージョン付きアセット-url)を参照)。`theme`(既定)ならテーマのバージョンが変わったとき、`build` や `false` ならデプロイのたびに変わります。
- 新しいワーカーは、このサイトの古いキャッシュだけを削除します。

`sw.js` はデプロイのたびに変わり、ブラウザーはそれで新しいワーカーを見つけます。Cloudflare などの CDN をサイトの前に置いている場合は、`/sw.js` を長いエッジキャッシュから外してください(そのパスのキャッシュを迂回するキャッシュルール)。そうしないと、エッジのコピーが期限切れになるまで訪問者は古いワーカーを使い続けます。

## オフにする

ファイルを削除するだけではいけません。すでに訪問者の端末にあるワーカーが古いコピーを返し続けます。代わりに次の順で進めます。

1. `enabled: kill` にしてデプロイします。`sw.js` はこのサイトのキャッシュを削除し、自分自身を取り除いて、開いているページを読み込み直すワーカーになります。マニフェストのリンクと登録スクリプトはなくなります。
2. 再訪する読者が受け取れるよう、1 週間そのままにします。
3. `enabled: false` にするか `pwa` を消してから、`manifest.webmanifest`、`sw.js`、オフラインページを削除します。

`enabled: false` でも `sw.js` は自分を取り除くワーカーになるので、この手順を踏まずに設定をオフにしても片付きます。ファイルを削除するまで `modootoday-check` が警告します。

## 端末に残るもの

インストールで増えるのはショートカットとアプリのウィンドウです。ワーカーは Cache Storage の `mt:<baseurl>/:` の下に、テーマのファイル、訪れたページを最大 50、画像とフォントを最大 60 保存し、Cookie や `localStorage` には何も加えません。テーマはどこにもデータを送らず、プッシュ、バックグラウンド同期、永続ストレージを求めず、分析ツールを加えず、インストールの案内を自分から出しません。インストールを提案するタイミングはブラウザーが決めます。訪問者はほかのアプリと同じく、ブラウザーのアプリ一覧やホーム画面からアプリを削除し、ブラウザーの設定でサイトのデータを消すとワーカーが保存したものも消えます。ブラウザーが自分で消すこともある(Safari では数週間訪問がないとき)ため、オフラインで読む機能はベストエフォートです。

## コンテンツセキュリティポリシー

マニフェストはサイト自身のファイルなので、`default-src 'self'` のポリシーで許可されます。ワーカーとワーカーが読み込むスクリプトもサイトのファイルです。ポリシーの `default-src` がそれより狭い場合は `manifest-src 'self'` と `worker-src 'self'` を加えます。[CSP](../csp/) を参照してください。
