# Translations are localized from English, not literal

## Context

The theme ships English, Korean and Japanese docs, README.ko.md, example guides and interface strings in `_data/i18n/<lang>.yml`. English is already canonical (adr:modootoday/20261029201227), but earlier translations were close to word-for-word, used different words for the same concept on different pages, and the English interface file had fewer keys than the translations, so nothing showed which keys or pages had drifted.

## Decision

1. English stays canonical. A translation says the same thing as the English page: no added or dropped facts, options, steps or caveats. When they disagree, English wins and the translation is fixed.
2. Translations are localized, not literal. Each sentence is rewritten the way a native technical writer would say it: natural word order and idiom, the language's own sentence length, no calques ("~를 가진", "〜を持つ" for "has"), no stacked nouns copied from English. Headings may be rephrased to read naturally as long as they keep the same section and anchor role.
3. Tone (replaced by adr:modootoday/20261030043745: Korean docs use 합니다체). Korean docs use 해요체; 합니다체 only where a formal register is expected (legal notices, security policy). Japanese uses です・ます体; headings, table cells and list fragments are plain noun phrases. Interface strings are short labels in both languages, not sentences.
4. Terminology follows the glossary (now i18n/glossary.yml, per adr:modootoday/20261030043745). The same English term always gets the same translation within a language.
5. Never translated: code blocks, inline code, file names and paths, Liquid, front matter keys and values the theme reads, component and section names, `status:`/`tag:`/`since:`/`kbd:` values, CSS classes and `--mt-*` tokens, configuration keys, command names and options, URLs, product names (Jekyll, GitHub Pages, RubyGems, modootoday) and the alert markers `[!NOTE]` and friends. Interface labels in `_data/i18n/<lang>.yml` are translated; their keys are not.
6. Numbers, dates and plurals. Numbers use ASCII digits with the language's grouping (1,000). Dates in prose follow the language (2026년 10월 30일, 2026年10月30日); machine dates stay ISO 8601. Korean and Japanese have no grammatical plural: drop English plural markers, and do not add 들 or たち to technical nouns. Units and versions keep the English form (`1.0.0`, 360 px).
7. Spacing and punctuation. Korean follows standard 띄어쓰기, uses ASCII punctuation and puts no space between a word and its particle, including after code (`theme`를). Japanese uses full-width 、。（）「」 in prose, no space between Japanese characters, and one half-width space between Japanese text and Latin words or inline code. Quotation marks: Korean uses “ ” or ‘ ’, Japanese uses 「」 and 『』. Code and keys keep ASCII punctuation.
8. Sync. There is no per-page sync marker: a change to an English page updates its translations in the same pull request when the contributor can, and otherwise the pull request lists the pages left behind. Translated pages start with the existing note that English is canonical.
9. Missing translations fall back to English. An interface key missing from `_data/i18n/<lang>.yml` uses the theme catalog for that language, then the English label; a page that has no translation is simply absent from that language and the language switcher points to that language's home. `modootoday-check` reports a translation key that is not in the default-language file as an error, a missing key or a translated page without a default-language page as a warning.
10. Adding a language. Add `_data/i18n/<code>.yml` with every key of `en.yml`, the language's endonym as `language:`, the code in `modootoday.languages`, a `<code>/` folder with at least `index.md` and a front matter default `lang: <code>`, and a glossary column in TRANSLATING.md. Right-to-left languages get `dir="rtl"` from the language code; set `direction:` in the i18n file only to override. Check that the page font covers the script before shipping the language.

11. Supported languages. The docs site targets 23 languages, listed once in `docs/_data/languages.yml` (code, endonym, English name, dir): en, zh-CN, zh-TW, ja, ko, tr, ru, vi, th, de, es, fr, uk, pl, pt-BR, ar, fa, id, it, el, ml, ur-Latn, ro. Every language has a complete interface catalog; `direction:` is set explicitly in each catalog so that ur-Latn (Roman Urdu) stays left-to-right while ar and fa are right-to-left. A language joins `modootoday.languages` (and so the switcher, hreflang and sitemap) once its home page is localized.
12. Per-language tone. zh-CN and zh-TW: plain written register, full-width punctuation, no spaces between Han characters but a space around Latin words; zh-TW uses Taiwan terms (佈景主題, 搜尋, 選單). de, fr, es, it, pt-BR, ro, pl, uk, ru, el, tr: address the reader politely and consistently (de/fr/ru/uk/pl/el: formal Sie/vous/вы/ви/Pan or impersonal forms; es/it/pt-BR/ro: informal tú/tu/você/tu as in common developer docs), keep sentences short. fr uses a narrow space before ; : ! ? and typographic apostrophes. vi, id, th, ml: neutral polite register; th has no spaces between words, only between phrases. ar and fa: Modern Standard Arabic and formal Persian, right-to-left, Latin code stays left-to-right; fa uses the zero-width non-joiner where standard. ur-Latn: Roman Urdu as written by developers, with common English technical words kept.
13. Labeled English fallback. A page that is not localized is not half-translated: the language shows the English page with a visible fallback notice (`fallback.notice`), `noindex`, and it is left out of hreflang alternates and the sitemap.
14. Built-in catalogs, zero copy. The gem's `i18n/<code>.yml` files are the canonical catalogs (`en.yml` is the key registry). A theme cannot ship `_data` on GitHub Pages, and Liquid cannot parse YAML, so `script/i18n-build` compiles them into Liquid includes: `_includes/modootoday/i18n/<code>.html` (one language packed into a single captured string, cheap to parse because Jekyll 3 re-parses includes on every render), a loader `_includes/modootoday/i18n.html` that includes only the page language's file (exact code, else the base subtag, never `ur` → `ur-Latn`) and resolves each key in one assignment (site `_data/i18n/<lang>.yml`, then that file, then English, which is inlined in the loader), and `_includes/modootoday/t.html` for lookups by key with `%{n}`/`%{name}` substitution. Resolution: site, then theme catalog, then English. Direction comes only from the language's own catalog or front matter, never from English. Layouts and includes contain no inline English labels and JavaScript reads labels from data attributes. Generated files are committed; CI fails when they are stale, keys are missing or placeholders differ. Only `.yml` is accepted. The loader runs once per layout render. On the GitHub Pages build (Jekyll 3.10) the docs site builds about 2% slower (median 3.61 s vs 3.54 s over 5 interleaved runs on 57 pages, within run-to-run noise; about +7% before the icon includes landed), down from 15–20% for a first version that assigned every key three times; parse cost, not rendering, dominates.

## Consequences

Translations read as native docs and use one term per concept. The checker makes drift visible without a build plugin, so it works on classic GitHub Pages. Reviewers judge a translation against the English page and the glossary rather than against a literal rendering, and new languages follow one documented path.
